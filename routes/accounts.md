2) Detailed SOP (Training Version)
Document Title:

STANDARD OPERATING PROCEDURE (SOP)
Accountant Operations – School Finance System
Department: Accounts
Users: Accountant, Principal (review), Admin (support)

1. Purpose
To standardize how accountants:

Configure student fee structures (vote heads),
Record student payments,
Allocate payments to vote heads (auto or manual priority),
Manage finance transactions and payment vouchers,
Print and file compliant accounting documents.
2. Scope
This SOP covers:

Student Finance
Fee Structures
Finance / Payment Voucher
Daily reconciliation and controls
3. Roles and Responsibilities
3.1 Accountant
Maintain accurate fee accounts
Capture all receipts and allocations
Generate vouchers and transaction records
Print and file supporting documents
Perform end-of-day balancing
3.2 Principal/Approver
Authorize voucher disbursements
Review financial summaries and exception reports
3.3 System Admin (technical)
Maintain uptime, backups, roles, and data integrity
4. Preconditions Before Use
Accountant user account active and role assigned.
Vote-head tables and fee-structure setup completed.
Current year fee structures available (e.g., Day Scholar, Boarder).
Printer functional for receipts/vouchers.
5. Operational Procedures
5.1 Login and Navigation
Login to system.
Use sidebar:
Student Finance
Fee Structures
Finance
5.2 Create/Update Fee Structures
Frequency: Start of year or upon official fee revision.

Open Fee Structures.
Create structure:
Name
Year
Category (day_scholar / boarder)
Add lines by vote head:
Govt capitation amount
Parent total amount
Term split (T1, T2, T3)
Save structure.
Verify totals and line order.
Control: A structure in use by student accounts should not be edited without approval.

5.3 Set/Update Student Fee Account
Open Student Finance.
Under Set / Update Student Fee Account:
Select student
Select fee structure
Confirm/adjust total due
Add sponsor details if applicable
Save.
Confirm account appears in Student Fee Accounts table.
Control: Ensure each student is assigned the correct structure category.

5.4 Record Student Payment (Auto Allocation)
Use when no special instructions are given by parent.

In Record Student Payment:
Select student
Enter amount, method, date
Receipt no (optional if auto-generated)
Keep priority allocation OFF.
Save.
Print receipt.
System behavior:

Creates unique receipt number
Allocates against parent outstanding balances in configured order
Updates account paid and balance
5.5 Record Student Payment (Manual Priority Allocation)
Use when parent specifies allocation by vote head.

Example:

Lunch = 1,500
Remedial (RMI) = 500
Steps:

Enable Use vote-head priority allocation.
Add vote-head rows and amounts.
Confirm:
Split total equals payment amount
Difference = 0.00
Save payment.
Print receipt.
System behavior:

Records per-vote-head allocation lines
Keeps allocation audit order
Control: Never save when Difference ≠ 0.00.

5.6 Verify Posting Accuracy
After each payment:

Check Payment Receipts list for new receipt.
Check Student Fee Accounts paid/balance updated.
Click View Vote Heads and confirm amounts posted to intended vote heads.
Print statement if parent requests.
5.7 Finance Transactions
Open Finance.
Record school-level income/expense transactions.
Include clear category, description, amount, and reference.
Save and verify in transaction list.
5.8 Payment Vouchers
Create voucher in Finance.
Ensure auto-generated voucher number appears.
Fill payee, purpose, amount, payment method.
Save and print voucher.
Capture required signatures:
Principal approval
Accountant signature
Payee signature
5.9 Printing and Filing Standards
For every collection/disbursement:

Print receipt/voucher immediately
File by date and number sequence
Keep signed hardcopy where required
6. End-of-Day Closing Procedure
Reconcile:
Total receipts captured vs physical cash/bank submissions
Finance income/expense totals
Confirm all receipts and vouchers are printed and filed.
Resolve mismatches before close.
Share daily summary with principal/admin.
7. Error Handling Guide
7.1 Vote Head Breakdown empty
Confirm student has fee structure assigned
Save account and refresh page
If still empty, report to admin for ledger backfill check
7.2 Allocation total mismatch error
Correct vote-head rows until split total equals payment amount
7.3 Receipt missing in list
Refresh page / clear search filters
Confirm save response succeeded
7.4 Missing vote-head allocation on printed receipt
Check if payment was posted with allocation rows
Reopen receipt print after refresh
8. Internal Controls & Audit Rules
Do not share credentials.
Do not delete records without approval trail.
Keep all references and narrations complete.
Use consistent receipt/voucher numbering.
Maintain chronology in physical files.
Escalate suspicious entries immediately.
9. Training Checklist for New Accountant
 Can create/update fee structure
 Can assign student fee structure
 Can post normal payment
 Can post manual vote-head allocation
 Can print receipt and verify allocation table
 Can create and print payment voucher
 Can perform end-of-day reconciliation
10. KPI Suggestions (for management)
Daily receipt posting completeness (%)
Unallocated payment count
Outstanding balances by vote head
Voucher turnaround time
Reconciliation variance trend
